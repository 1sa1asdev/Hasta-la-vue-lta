## Startup and scaling

The Container App is configured with `minReplicas: 0` and `maxReplicas: 1`. This keeps the staging environment at zero replicas while idle, but the first request after idle starts all four containers in the single replica: client, API, PostgreSQL, and MongoDB.

## Consequences

- Staging is publicly reachable over HTTPS without exposing the API port directly.
- The API and client are deployed from immutable commit-tagged GHCR images.
- JWT and database credentials are generated by the setup script and stored as Azure Container Apps secrets.
- PostgreSQL and MongoDB run as sidecars in the same Container Apps replica. Their data is ephemeral and should not be treated as production data.
- Scaling to zero reduces idle cost but makes the first request slower after inactivity.
